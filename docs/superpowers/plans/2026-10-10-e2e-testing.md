# E2E Test Suite & Launch-Readiness Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A permanent Playwright E2E suite covering every feature × role × locale, plus a launch-readiness report of every bug/gap found while writing it.

**Architecture:** A Docker-free reset script rebuilds a dedicated cloud Supabase project (`pckrdspetqcdbmcrqapx`) from `supabase/migrations/*.sql` + `e2e/seed.e2e.sql` before each run. Playwright builds and starts the app as a production build with mock vendors, logs in once per role (storageState), and runs one spec file per feature area with automatic console/5xx/missing-translation guards.

**Tech Stack:** Next.js 14 App Router, Supabase (supabase-js + `pg` for resets), `@playwright/test`, `@axe-core/playwright`, Stripe SDK (signed test webhooks), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-10-e2e-testing-design.md`

## Global Constraints

- Test DB is **only** project ref `pckrdspetqcdbmcrqapx`; `e2e/reset-db.ts` must refuse any other ref. Never touch the `.env` project (`dltahrjljptsmvksgqjl`) — it holds real users.
- App under test runs as `next build && next start` on port **3100** with `NODE_ENV=production` and `ALLOW_MOCK_PROVIDERS=true`.
- Every vendor key (`LLM_API_KEY`, `HEYGEN_API_KEY`, `HEYGEN_AVATAR_ID`, `HEYGEN_VOICE_ID`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `AYRSHARE_API_KEY`, `NEWSDATA_API_KEY`) is forced to the empty string in the E2E server env so mocks are used. Next.js auto-loads `.env` in production mode and **does not override vars already present in `process.env`**, so explicit empty strings win.
- Seed passwords: all `e2e-pass-123`.
- Bugs found: write the test for **correct** behaviour, mark `test.fail(true, 'E2E-NNN: <title>')`, log in `docs/e2e/launch-readiness.md`. Do not fix app code in this plan.
- No commits — the owner reviews and commits. Each task's last step is "stage for review" (`git add` only) instead of commit.
- No fixed sleeps (`waitForTimeout`) in specs; use web-first assertions (`expect(locator).toBeVisible()`, `expect.poll`).
- Spec files are `*.spec.ts` under `e2e/`; Vitest must exclude `e2e/**`.

## Review Focus

1. **E2E server silently pointed at the wrong DB** (e.g. `.env` Supabase URL wins) → global setup must prove it is talking to the test DB (login as `admin-e2e@e2e.test`, a user that exists only in the seed) before any spec mutates data. Owned by Task 4.
2. **Real vendor adapters activating during E2E** (a key leaks in from `.env`) → a canary test asserts AI draft returns the Mock generator's output. Owned by Task 4.
3. **Unauthenticated `/api/*` callers** (no header, wrong bearer, wrong cron secret, bad Stripe signature) → each API route gets explicit 401/400 tests. Owned by Tasks 13, 14, 16.
4. **Double-submit / replay** (same Stripe event delivered twice, same monitoring item ingested twice, publish cron run twice) → idempotency tests. Owned by Tasks 13, 14, 16.
5. **Mobile viewport** (Pixel 7) on every page → no horizontal overflow, primary actions reachable. Owned by Task 18.

- [ ] **Step 3: Implement `e2e/reset-db.ts`**

```ts
// Docker-free rebuild of the E2E Supabase project. Wipes the `public` schema,
// replays every migration in filename order, ensures the `media` storage
// bucket, applies the E2E seed, and reloads PostgREST's schema cache.
// Guarded: refuses any project not in ALLOWED_REFS.
import { readFileSync, readdirSync } from 'fs';
import { join, resolve } from 'path';
import { Client } from 'pg';

export const ALLOWED_REFS = ['pckrdspetqcdbmcrqapx'] as const;

function refFromDbUrl(dbUrl: string): string | null {
  const u = new URL(dbUrl);
  const fromUser = u.username.match(/^postgres\.([a-z0-9]{20})$/)?.[1];
  const fromHost = u.hostname.match(/^db\.([a-z0-9]{20})\.supabase\.co$/)?.[1];
  return fromUser ?? fromHost ?? null;
}

export function assertAllowedTarget(dbUrl: string, supabaseUrl: string): string {
  if (!dbUrl) throw new Error('E2E_DATABASE_URL is empty');
  const dbRef = refFromDbUrl(dbUrl);
  const apiRef = new URL(supabaseUrl).hostname.split('.')[0];
  if (!dbRef || !(ALLOWED_REFS as readonly string[]).includes(dbRef) || dbRef !== apiRef) {
    throw new Error(`Refusing to reset: db ref=${dbRef} api ref=${apiRef} not in allow-list ${ALLOWED_REFS.join(',')}`);
  }
  return dbRef;
}

const ROOT = resolve(__dirname, '..');

export async function resetDb({ log = console.log }: { log?: (m: string) => void } = {}) {
  const dbUrl = process.env.E2E_DATABASE_URL ?? '';
  const ref = assertAllowedTarget(dbUrl, process.env.NEXT_PUBLIC_SUPABASE_URL ?? '');
  log(`[e2e:db] resetting ${ref}`);
  const client = new Client({ connectionString: dbUrl, ssl: { rejectUnauthorized: false } });
  await client.connect();
  try {
    await client.query(`drop schema if exists public cascade; create schema public;
      grant usage on schema public to postgres, anon, authenticated, service_role;
      grant all on schema public to postgres, service_role;
      alter default privileges in schema public grant all on tables to postgres, anon, authenticated, service_role;
      alter default privileges in schema public grant all on sequences to postgres, anon, authenticated, service_role;
      alter default privileges in schema public grant all on functions to postgres, anon, authenticated, service_role;`);
    const dir = join(ROOT, 'supabase/migrations');
    for (const f of readdirSync(dir).filter((f) => f.endsWith('.sql')).sort()) {
      try { await client.query(readFileSync(join(dir, f), 'utf8')); }
      catch (e) { throw new Error(`[e2e:db] migration ${f} failed: ${(e as Error).message}`); }
      log(`[e2e:db]   ✓ ${f}`);
    }
    await client.query(`insert into storage.buckets (id, name, public) values ('media','media',true)
      on conflict (id) do update set public = true;
      delete from storage.objects where bucket_id = 'media';`);
    await client.query(readFileSync(join(ROOT, 'e2e/seed.e2e.sql'), 'utf8'));
    log('[e2e:db]   ✓ seed.e2e.sql');
    await client.query(`notify pgrst, 'reload schema'`);
  } finally {
    await client.end();
  }
}

if (require.main === module) {
  resetDb().catch((e) => { console.error(e.message); process.exit(1); });
}
```

Note: `delete from storage.objects` may be blocked by Supabase's storage-protection trigger; if so, replace with removal via `adminDb.storage.from('media').list/remove` using supabase-js, and record it in the report as a non-issue.

import { readFileSync, existsSync } from 'fs';
import { resolve } from 'path';

export const BASE_URL = 'http://localhost:3100';
export const E2E_SECRETS = {
  cron: 'e2e-cron-secret',
  monitoring: 'e2e-monitoring-secret',
  stripeWebhook: 'whsec_e2e_test_secret',

} as const;

function loadDotEnvE2E(): Record<string, string> {
  const p = resolve(__dirname, '../.env.e2e');
  if (!existsSync(p)) return {};
  return Object.fromEntries(readFileSync(p, 'utf8').split('\n')
    .filter((l) => /^[A-Z0-9_]+=/.test(l))
    .map((l) => [l.slice(0, l.indexOf('=')), l.slice(l.indexOf('=') + 1)]));

- **Server layer** for each forbidden combination: invoke the action anyway. Technique: as an *allowed* role, record the server-action POST (`page.waitForRequest(r => r.method()==='POST' && r.headers()['next-action'])`) and capture its `next-action` id + body; then replay the same request with the forbidden role's cookies via `asRole(forbidden).request.post(url, { headers: { 'next-action': id, ... }, data: body })`; assert the record did **not** change in `db` (e.g. `content_items.status` unchanged) and no approval row was inserted. Put this capture/replay in `e2e/helpers/server-action.ts`:

```ts
import type { Page, Request } from '@playwright/test';
export type CapturedAction = { url: string; headers: Record<string, string>; body: string };
export async function captureAction(page: Page, trigger: () => Promise<void>): Promise<CapturedAction> {
  const reqP = page.waitForRequest((r: Request) => r.method() === 'POST' && !!r.headers()['next-action']);
  await trigger();
  const r = await reqP;
  const h = r.headers();
  return { url: r.url(), body: r.postData() ?? '',
    headers: { 'next-action': h['next-action'], 'content-type': h['content-type'], accept: 'text/x-component' } };
}
export async function replayAction(page: Page, a: CapturedAction) {
  return page.request.post(a.url, { headers: a.headers, data: a.body });
}
```

Capture from a *throwaway* content item created in the test (not seed items) so the allowed role's real action doesn't consume shared state; for the replay target, re-point the body's content id to a fresh in-review item (the body is form-encoded or JSON — inspect and substitute the id string).
- Admin pages: every `/admin*` route as each non-admin role → redirected or 403/404, and admin nav link absent.
- Admin as `admin`: can open each `/admin*` page.
